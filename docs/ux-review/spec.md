**Non-negotiables for every implementer**

- Respect `AGENTS.md`: no fiction generation, no fake agent status, no hidden external execution, demo/connected separation, provenance on every record, docs aligned with code.
- Copy voice: warm, direct, adult, peer-level. She is the expert. No emoji in system copy. No cutesy diminutives where they belittle her work. Say what a thing does; do not pile up caveats.
- Names: **Kira Stanley** is her pen name (byline, product name "KIRA OS"). **Cassandra / Cassy** is her, at the business desk. The workspace AI is **Raven**. Never use "Kira" as the actor that reads, learns or saves. Never refer to her in the third person on her own screens. Never print "Michael"; say "the workspace owner" (or the owner's identity from the access record when a UI already has it).
- Keep every pinned string green or update its test **in the same change** (`docs/ux-review/brief.md` lists them). Never delete or skip a test.
- Work only in the files your workstream owns (below). New styles go in your workstream's own CSS file or an existing per-feature file; **only W6 edits `app/globals.css`**. If you need a new global class, add it to your own CSS file and note it in your final report.
- Validate before you finish: `npx tsc --noEmit`, `npx eslint <your files>`, and the unit tests that cover your files (`npx vitest run <file>`). The verifier runs the full `npm run check`, `npm run test:e2e` and `npm run test:e2e:connected`.
- Do not "improve" anything the judges listed under *what works* (draft protection choreography, version-conflict guard, focus management, spoiler defaults, provenance badges, the typography pairing).

Priority: **P0** = must ship before Cassy sees it · **P1** = ship in the same run if it fits · **P2** = after the demo / needs the owner.
