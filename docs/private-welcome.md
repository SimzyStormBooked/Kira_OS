# Email-independent welcome links

Existing confirmed workspace members can receive a single-use Supabase magic link directly from the workspace operator. This does not send email, create accounts, grant membership, change a password, or enable public signup. It is an additional sign-in path using the same private workspace authorization.

The trusted local operator verifies the existing account and its workspace membership before calling `auth.admin.generateLink({ type: "magiclink", email })`. Administrative credentials remain local and never enter the Vercel runtime. Only the generated `properties.hashed_token` is placed in `https://kira-os-dusky.vercel.app/welcome#token_hash=…`. Treat that complete URL as a temporary credential and deliver it only to its intended person. Supabase controls expiration and rejects reuse; generating another link can invalidate an earlier one.

The URL fragment is captured in browser memory and immediately removed from the address bar/history. It is not stored in browser storage or rendered into the page. GET requests and text-message previews do not consume the token. The recipient explicitly chooses **Enter my workspace**, which posts to the same-origin `/auth/welcome` endpoint. The endpoint accepts only bounded JSON, fixes the verification type to `magiclink`, verifies a newly returned session and account identity, then checks existing workspace membership under RLS. Failed membership verification clears the new local session. Normal HTTP-only, Secure, SameSite=Lax production cookies carry the verified session.

The landing page is public; workspace routes and data remain private. The page disables indexing and referrer sharing. No service-role key, administrative issuance endpoint, public invitation flow, or automatic email sender is added to the app. Existing email/password sign-in remains available after a link is used. If a link expires before use, the operator must issue a fresh one. An already authorized browser sees its verified email and **Continue to my workspace**, including on bare `/welcome` and previously used links. An explicit account-switch button remains available for a different private link; the app never silently assumes that the link belongs to the current account.

The permanent bookmark/share address is `https://kira-os-dusky.vercel.app/`. Existing sessions continue directly; signed-out visitors use their own email and password. Password choice in Settings can omit the temporary/current password only within 15 minutes of a server-verified OTP or magic-link authentication. The server independently checks the signed authentication-method timestamp and matching verified member identity on every setup submission; a refreshed token's issuance date does not renew this window. Outside that window, ordinary password changes still verify the current password. This is recent-authentication permission, not a claim that an account has never had a password. No real user's password is automatically changed by this flow.

Verification includes unit tests for request boundaries and failed authorization, simulated connected browser tests for click-only consumption and session behavior, and a real production sign-in with a sacrificial link before issuing an unconsumed delivery link. Test reports must never contain the token, complete private link, or session credentials.
